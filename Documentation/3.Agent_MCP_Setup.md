# Agent & MCP Setup — Phase 3

Phase 3 wires the **Agno** agent to send all LLM traffic through **Envoy** (with **AI Gateway ext_proc** for credential injection and body inspection), and attaches **two stdio MCP servers** for filesystem and SQLite tools.

## Install Agno in venv
```bash
$ python3 -m venv venv && source venv/bin/activate && pip install -q agno openai 'mcp>=1.6,<2'

$ npm install --prefix /home/amit/ProtocolNine/mcp-servers @modelcontextprotocol/server-filesystem mcp-server-sqlite
```

## Architecture

### End-to-end path: agent → AI Gateway → OpenAI

The agent does **not** call OpenAI directly. It uses the OpenAI SDK shape with a overridden `base_url`, so every chat completion goes to Envoy on port 8080.

```text
  Agno Agent (Python)
       |
       |  OpenAI-compatible HTTP
       |  POST http://127.0.0.1:8080/v1/chat/completions
       |  Authorization: Bearer gateway-injected  (placeholder)
       v
+---------------------------+
|  Envoy Proxy  :8080       |
|                           |
|  listener ext_proc -------+---- gRPC ----> AI Gateway ext_proc :1063
|  (BUFFERED body)          |              - inspect body / headers
|                           |              - inject Authorization
|  router → openai_cluster  |
|  upstream ext_proc -------+---- gRPC ----> (cluster-level key injection)
|                           |
+-------------+-------------+
              | HTTPS
              v
      api.openai.com:443
```

**Sequence (one LLM call):**
```
Agno_LLM_Client                                   Envoy Proxy           AI Gateway:1063
  ---HTTP POST `127.0.0.1:8080/v1/chat/completions`-->
                                                      --- send over gRPC -->
                                                                        Read body
                                                                        Add real `Authorization` from `config/.env`
                                                      <--------------------
                                                Read openai_cluster
                                                from envoy.yaml
                                                    ---------------------> api.openai.com
                                                    <---------------------------

```
1. Agno `OpenAIChat` builds JSON body (model, messages, tools schema from MCP).
2. HTTP POST to `127.0.0.1:8080/v1/chat/completions` — agent thinks this is the LLM API.
3. Envoy **listener** `ext_proc` filter opens gRPC stream to AI Gateway (`127.0.0.1:1063`).
4. AI Gateway reads buffered body, may mutate headers (adds real `Authorization` from `config/.env`).
5. Envoy **router** selects `openai_cluster`; **upstream** `ext_proc` runs again at cluster level.
6. Envoy terminates TLS and forwards to `api.openai.com`.
7. Response returns through ext_proc (token counting path) back to the agent.

### MCP transport split

```text
  Agno Agent
       |
       +--- LLM calls ----------> Envoy :8080 ----> AI Gateway ----> OpenAI
       |
       +--- MCP filesystem -----> stdio subprocess (direct, NOT via Envoy)
       |
       +--- MCP sqlite ---------> stdio subprocess (direct, NOT via Envoy)
```

Stdio MCP traffic stays inside the agent process tree. Only HTTP-based tools (e.g. fetch) would be routed through Envoy — not configured yet.

## Configuration

### LLM via Envoy (Agno)

```python
OpenAIChat(
    id="gpt-4o-mini",
    api_key="gateway-injected",          # placeholder — real key injected by AI Gateway
    base_url="http://127.0.0.1:8080/v1", # Envoy listener, not api.openai.com
)
```

### MCP servers (stdio)

| Server | npm package | Command |
|--------|-------------|---------|
| Filesystem | `@modelcontextprotocol/server-filesystem` | `node mcp-servers/node_modules/.bin/mcp-server-filesystem workspace/` |
| SQLite | `mcp-server-sqlite` | `node mcp-servers/node_modules/.bin/mcp-server-sqlite --db workspace/data/index.db` |

Agno `MCPTools` requires the command to start with an allowed executable (`node`, `npx`, etc.) — not a bare path to the bin script.

### HTTP MCP via Envoy (deferred)

Phase 0 planned `mcp-server-fetch` with the agent pointing at Envoy. Current `config/envoy.yaml` only defines the OpenAI upstream cluster. Adding fetch requires either:

- A second listener/route (e.g. `/mcp/*` → upstream fetch proxy), or
- Dynamic forward proxy cluster for arbitrary HTTPS hosts.

This is left for a later phase so Phase 3 focuses on LLM + stdio tools.

## Request shape and MCP call flow (interview notes)

### LLM request (via Envoy)

Agno sends standard OpenAI Chat Completions JSON:

```json
{
  "model": "gpt-4o-mini",
  "messages": [{"role": "user", "content": "..."}],
  "tools": [ ... MCP tool schemas ... ]
}
```

- **Host seen by Envoy downstream:** `127.0.0.1:8080`
- **Path:** `/v1/chat/completions`

### MCP call flow (stdio)

1. Agent decides to call a tool (e.g. `write_file`).
2. Agno sends JSON-RPC over stdin to the MCP server subprocess.
3. MCP server executes locally (filesystem or SQLite).
4. Result returned over stdout to Agno.
5. Agno may issue another LLM call with tool results — that LLM call **does** appear in Envoy access logs.

### What appears where

| Traffic | Visible in Envoy access log? | Visible in extproc log? |
|---------|------------------------------|-------------------------|
| LLM chat completions | Yes | Yes (body inspection / token path) |
| MCP filesystem/sqlite | No (stdio) | No |
| HTTP MCP (future fetch) | Yes (if routed via Envoy) | Depends on route |


## Known limitation

**OpenAI account has no credits** (`insufficient_quota` / HTTP 429). Infrastructure is correct:

- Agent → Envoy → ext_proc → OpenAI path works.
- Credential injection works (OpenAI responds with billing error, not 401).
- Full agent task (report + SQLite row) requires adding credits or switching to a funded API key in `config/.env`.

After adding credits, re-run:

```bash
bash scripts/run_agent.sh
ls workspace/reports/
sqlite3 workspace/data/index.db '.tables'
```
