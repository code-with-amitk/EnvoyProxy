# Design Discussion — Part D §5.3

Interview: design an enhancement (no code). Explain **where**, **what to change**, **config**, **tradeoff**.

---

## Problem

The interviewer asks you to **design** a new gateway feature — not implement it. Topics: DLP, content safety, code risk, multi-agent (A2A), or chatbot parsers.

**Read first to understand the baseline:**

```text
Documentation/5.Policy_Controls.md              what you already built (Lua, rate limit, routing)
Documentation/Checklist/Trace.ai_gateway_server.go.md   how AI Gateway receives requests
Documentation/Checklist/Trace._envoy_proxy_ext_proc.cc.md   how Envoy calls AI Gateway
ai-gateway/internal/extproc/processor_impl.go   where prompt/response logic lives (L213, L495)
ai-gateway/internal/filterapi/filterconfig.go    where YAML config is defined
```

---

## Answer

Answer four things for any topic: **(1)** filter chain placement — Envoy Lua vs AI Gateway ext_proc; **(2)** which interface/file to extend; **(3)** new fields in `extproc.yaml` / `filterapi`; **(4)** latency and streaming tradeoff (fail-open vs fail-closed).

Simple rule: fixed string match → **Envoy Lua**. Needs parsed chat JSON or LLM response → **AI Gateway** after `ParseBody` (input) or `ProcessResponseBody` (output).

---

## How

```text
┌──────── Agent ────────┐
│  prompt / response    │
└──────────┬────────────┘
           ▼
┌──────────────────────────── Envoy :8080 (proxy) ────────────────────────────┐
│  ★ Envoy-only ★   Lua string match · local rate limit · path/cluster route │
│  ✗ not here       parsed JSON policy · LLM response scan · key injection   │
│                   ext_proc gRPC (forwards headers + body, does not decide)  │
└──────────────────────────────┬──────────────────────────────────────────────┘
                               │ gRPC
                               ▼
┌──────────────────────── AI Gateway :1063 ───────────────────────────────────┐
│  ★ AI Gateway ★   parse body · DLP · safety · code risk · parsers · A2A   │
│  Stream 1 routerProcessor    ProcessRequestBody L213  (input policies)       │
│  Stream 2 upstreamProcessor  inject key · ProcessResponseBody L495 (output)  │
│  mcpproxy :8081              MCP tool path (code risk · A2A CEL)             │
│  Config: filterapi → config/extproc.yaml                                     │
└─────────────────────────────────────────────────────────────────────────────┘

Rule: fixed string on raw body → Envoy Lua. Everything else → AI Gateway ext_proc (or mcpproxy).
```
