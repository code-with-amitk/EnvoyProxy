# 5.3.3 Code Detection & Risk Scoring

## Problem

Interview asks: *How to detect code in LLM replies, score risk (shell, network, priv-esc), and choose block vs quarantine vs annotate header?*

Coding agents may **run** what the LLM returns. The gateway should flag dangerous code **before** the agent executes it.

**Read first:**

```text
processor_impl.go L495          ProcessResponseBody — assistant text + tool_calls
apischema/openai/openai.go      ToolCalls JSON shape
endpointspec/endpointspec.go    already walks tool args for redaction
mcpproxy/handlers.go            MCP tools bypass LLM ext_proc — scan here too
```

---

## Answer

**AI Gateway** — not Envoy. Code lives inside parsed LLM responses (`tool_calls`, markdown fences) and MCP tool payloads; Envoy only sees opaque JSON.

Primary hook: **AI Gateway ext_proc** `ProcessResponseBody` L495. Also scan input prompt (L213). **MCP tools** bypass the LLM ext_proc path — same inspector in **AI Gateway mcpproxy** (`handlers.go`).

Score with enry + semgrep-style rules. Default **annotate** via headers; block for strict agents.

---

## How

```text

        │
        ▼
┌──────────────────────────── Envoy :8080 (proxy) ────────────────────────────┐

│              ext_proc gRPC forwards body only                                 │
└──────────────────────────────┬──────────────────────────────────────────────┘
                               │ gRPC (LLM path)
                               ▼
┌──────────────────────── AI Gateway :1063 ─ ext_proc ─────────────────────────┐
│  ProcessRequestBody L213   ★ scan pasted code in prompt (input) ★           │
│         ▼                                                                    │
│  Envoy → OpenAI                                                              │
│         ▼                                                                    │
│  ProcessResponseBody L495  ★ extract code · lang ID · rule scan · score ★   │
│         → annotate (x-ai-code-risk) / quarantine / block                     │
└─────────────────────────────────────────────────────────────────────────────┘

MCP path (no Envoy ext_proc on tool body):
┌──────────────────────── AI Gateway :8081 — mcpproxy ───────────────────────┐
│  handlers.go   ★ same Inspector on tool call + tool result ★               │
└─────────────────────────────────────────────────────────────────────────────┘
```
