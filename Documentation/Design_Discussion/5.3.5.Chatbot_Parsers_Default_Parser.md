# 5.3.5 Chatbot Parsers & Default Parser

## Problem

Interview asks: *How to normalize Slack/Teams/web/voice into OpenAI ChatCompletion before policy? What should a default parser do for unknown formats?*

DLP and safety need **one JSON shape**. Each chat channel sends **different JSON**.

**Read first:**

```text
mainlib/main.go L306              server.Register("/v1/chat/completions", …)
server.go L100                    processorForPath — path → processor
processor_impl.go L213            ProcessRequestBody — hook before/around ParseBody
endpointspec/endpointspec.go      Spec.ParseBody today
apischema/openai/openai.go        ChatCompletionRequest — target canonical form
```

---

## Answer

**AI Gateway only** — parsers turn Slack/Teams/widget/voice JSON into `ChatCompletionRequest`. Envoy cannot do this; it only routes by path.

Register integration paths in **AI Gateway `mainlib`**. Run channel parser in **`ProcessRequestBody` before `ParseBody`** (L213). Optional response formatting back to channel UI in same package. **Default parser** in AI Gateway for unknown formats.

Envoy may add a **route match** for `/integrations/slack/` → same cluster — routing only, not parsing.
